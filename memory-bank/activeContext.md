## v0.3 decisions

Calibrated AUC 0.667 / 0.670 / 0.701 / 0.736 / 0.770, below plain LightGBM because the model sees only 2013B.

- Reasons are value-only sentences (no direction), so a low-risk student can get "90 quiz interactions so far". Show reasons only for flagged cases; add direction wording after mentor feedback. SHAP comes from LightGBM `pred_contrib` (no `shap` dependency).

Week-4 recall gaps: gender 0.005, disability 0.005, region 0.105, imd_band 0.106, age_band 0.138, highest_education 0.155 (limit 0.10); the age gap comes from the 55+ group (n=118). Overall recall is 0.32 at 20% flagged.

On OULAD the model is blocked until a sign-off covers the four gaps. Gate compares calibrated week-4 AUC. MLflow store is local sqlite under `mlruns/` (git-ignored); registry tests take ~110 s.

## v0.4 decisions (2026-10-28)

- CSV connector: raw layer is all-text, keyed by the table's natural key, last row wins; cleaner rejects (never repairs) bad rows and cascades through foreign keys; exact duplicate rows are dropped silently, conflicting duplicates keep the later row. Report thresholds are untuned defaults: fail if an essential table is empty or >5% of a table's rows are rejected; warn on any issue or attendance/LMS data older than 3 days (marks and fees arrive in bursts, so they are not freshness-checked).
- Rows removed from a later file are not deleted from raw/core (connector only adds and updates).

- Case engine defaults (all untuned, in `app/cases/config.py`): red enter/exit 0.50/0.45, amber 0.30/0.25; rapid rise = +0.15 in 7 days and at least amber; 3 new cases per mentor per night (highest probability first, rest deferred and retried); 28-day reopen cooldown unless p >= 0.70; draft due 1 day, mentor review 3 days, follow-up 7 days, a third cycle escalates. Escalation routes to a person; it decides nothing about the student.
- Only a mentor can approve, only the case's own mentor (RBAC proper comes with auth); only the agent saves a plan; only the system runs the day-7 timer.
- Students with no row in `app.mentor_assignments` are reported as unassigned and get no case. Mentor ids are free text for now (OIDC subject later). Nothing populates `app.mentor_assignments` yet (admin API / import still to do).

## v0.4 nightly pipeline decisions (2026-10-28)
- One scheduled Celery task (`app.jobs.nightly.run_nightly`, 01:00 in `APP_TIMEZONE`, default UTC) runs `run_pipeline`: CSV ingest, `load_core_tables` + `build_snapshot`, scoring, `run_night`, reasons, `run_timers`. Scoring, cases, reasons and timers share one transaction. A data-quality `fail` keeps raw rows and the report, then raises `DataQualityFailed` before any scoring.
- Model: `Registry.load_production(week)` (raises `NoProductionModel`). Week = whole weeks since the term start; the latest trained week at or before it is used, falling back to earlier weeks, error if none. A night outside any term succeeds with `skipped` and still runs the timers; overlapping terms use the latest start.
- Reasons: top 3 per open case, stored in `app.case_reasons` (migration 0004), `fact_id` = `case-<id>/<feature>/<as_of>` (case reference, no student id), replaced on a re-run, refreshed every night for every open case. Mentor-only; nothing reads them yet.
- Worker refuses to start without `REDIS_URL`; settings added: `APP_TIMEZONE`, `CSV_DIR`, `MODEL_STORE`. `worker` and `beat` services are in `docker-compose.yml` (not run: no Docker).
- Generator takes `n_students` (default output unchanged). The 5,000-student timing test (budget 30 min, second night so it is a normal re-ingest) runs only with Postgres. Measured in CI (2026-10-28): the normal second night took 106 s (budget 1,800 s); the whole test, with data generation and the first load, 224 s.

## v0.4 audit chain decisions (2026-10-28)
- `gov.audit_log` (migration 0005): append-only (triggers refuse UPDATE, DELETE, TRUNCATE; a superuser can drop them, the chain detects that), `seq` numbered by the writer (not a sequence, so rollbacks leave no gap), `prev_hash` and `hash` unique so the database refuses a fork. Grants (INSERT + SELECT only) wait for the RBAC branch.
- Pure part `app/core/audit.py` (entry, canonical JSON, SHA-256 chain, `verify_entries`, `Anchor`); database part `app/core/audit_store.py` (`append` under an advisory lock in the caller's transaction, `verify`, `current_anchor`, CLI `python -m app.core.audit_store verify [--anchor SEQ:HASH] | anchor`). The lock is held to the end of the writing transaction; keep those short.
- `detail` refuses keys containing name, phone, mobile, email, roll, address, probability, score, band, risk, and any float. Audited so far: every case change (via `_event`, subject `case-<id>`) and the nightly run (`nightly.run` counts, `nightly.halted` on a data-quality fail). API writes get audited with the core APIs. Reads are not audited. An anchor (`seq:hash`) kept outside the database is the only defence against cut-off newest rows.

## v0.4 auth and RLS decisions (2026-10-28)
- Order changed to auth + RLS first, then core APIs, then an admin API, so no endpoint exists unprotected. Moodle connector moved out of v0.4 (`v0.4.0` is tagged without it). Mentors and staff may see the band, never the raw probability; nobody else sees either.
- `app/core/auth.py` (pure): RS256 only, `exp`/`iss`/`aud`/`sub` required, 30 s leeway, key from `JWT_PUBLIC_KEY` (PEM, `\n` escapes repaired) or `JWT_JWKS_URL`, roles from `JWT_ROLES_CLAIM` (dotted path allowed, default `roles`). Roles: admin > staff (HoD/counsellor) > mentor > faculty; a token with no known role is 403; students and parents have no role. Bad tokens get a bare 401 with no reason.
- `app/api/deps.py`: `current_principal`, `require_roles(...)`, `get_conn` (use `Depends(get_conn, scope="function")` so the transaction commits before the response). A 403 for an authenticated caller writes an `access.denied` audit entry (role + route template only); if that write fails the answer is still 403 and the error is logged. Missing auth configuration is a 503, never an open door.
- `app/core/db.py`: shared engine; `scope_to_principal` sets `app.user_id`/`app.role` (transaction-local) then `SET LOCAL ROLE app_api_role`. Migration 0007: that role owns nothing; RLS on app.cases, case_events, case_reasons, mentor_assignments, gov.audit_log. Mentor: own mentees' rows; staff/admin: all; faculty: none; unknown or missing identity: nothing; only admin writes mentor assignments and reads the audit log; no role can update or delete audit rows. No grants on core, raw, restricted, ml or app.risk_scores. `gov.audit_head()` (security definer) lets any writer find the chain end. The nightly job and migrations run as the table owner, which bypasses RLS (no second worker role). The role is created if missing, left in place on downgrade, and needs CREATEROLE; the API login must be allowed to `SET ROLE app_api_role`.

## v0.4 core API decisions (2026-10-28)

They check token required on every `/api` route, no score-like response field (band only on the case models), faculty refused before the database opens.

## v0.4 admin API decisions (2026-10-28)
- `app/api/admin.py`, admin only (mentor, staff, faculty get 403 before any data is read): `PUT /api/admin/mentor-assignments/{student_id}` (`{mentor_id}`, trimmed, max 128, no control characters, extra fields refused), `GET /api/admin/nightly/latest`, `GET /api/admin/audit/verify?anchor=SEQ:HASH`.
- `assign_mentor` (`app/cases/store.py`) runs under the admin identity in one transaction: upserts the assignment, moves the student's open case (event `reassigned`, actor `admin`), and audits. A closed case keeps the mentor who handled it; a reopen takes the current assignment. Setting the same mentor writes nothing, except that it still moves an open case that drifted from the assignment (CSV changes do not move open cases). Unknown student is 404 (foreign key), the savepoint keeps the transaction usable.
- Audit entries: `case.reassigned` (subject `case-<id>`) and `mentor_assignment.set` (subject `student-<id>`, detail `changed`, `cases_moved` only). No mentor-student pairing in any audit detail or case event. Latest run shows only whitelisted count keys. Staff cannot read the run or the audit check (admin only, by decision).
- No unassign endpoint (a student with no mentor gets no case). Reasons stay visible to mentor and staff only; admin gets none (confirmed).
- `tests/api/conftest.py` shares the `api` and `pems` fixtures; the new database tests are in the existing `cases, api` shard. `.gitleaksignore` got one more narrow fingerprint (roadmap prose, commit 839ab07).
